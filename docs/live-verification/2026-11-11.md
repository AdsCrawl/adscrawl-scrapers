# 失败项修复与真实复测报告

日期：2026-11-11（Asia/Shanghai）。本轮运行已结束，仍有未通过项。

本轮覆盖上次全站审计中 **55 个失败、11 个部分通过的站点，共 66 个**；此前整套通过的 15 个站点不在本轮范围内。因此，这不是一份新的“81 个站点全部可用”声明。

结果：**4 个整套通过、15 个部分通过、43 个未通过、3 个在限时内未完成、1 个按要求跳过后续测试（DHL）**。共 78 次站点或指定用例运行，逐次时间、退出码、用例结果和错误代码见 [JSON 证据](2026-11-11.json)。DHL 在用户要求跳过前的一次运行返回空轨迹，之后未再测试。

## 本次修复

- **Google Play**：CDP 临时导航失败时，普通 GET 可通过 SDK 的 HTML API 备用路径重试一次；缺少应用数据明确报错，不再静默遗漏应用。最新 US 整套测试 3/3 通过，包括 WhatsApp、Spotify 详情、评论和搜索。
- **Booking.com**：失败后先释放命名浏览器会话，再创建重试会话，修复并发为 1 时的 `SESSION_LIMIT`。伦敦 Garden Court Hotel 的详情及 61 天价格日历通过字段校验；后续法国酒店样例超时，整套仍未通过。
- **eBay**：首页拒绝不再阻断后续商品请求；识别真实 403 错误页，缺失搜索计数时给出明确错误。最新商品详情和变体通过，搜索仍失败。
- **AliExpress**：商品名称未加载时不再返回成功；修复 K/M 销量、千位分隔符和缺失划线价的解析。商品单项复测曾通过，随后整套商品请求超时、搜索隧道失败；评论和分类通过。保留两轮记录，不认定为稳定恢复。
- **Goibibo**：酒店搜索传入 `cityCode`、紧凑日期和印度市场参数，页面能正确初始化目的地。酒店列表接口仍未出现；首轮航班通过，后续复测失败。
- **Nordstrom**（目录名 `nordstorm-scraper`）：识别验证页、稳健提取内嵌配置并限制等待时间。捕获的 HTML 确实为验证页；在线请求仍有超时。
- **Target / Redfin**：保留真实访问错误，避免以缺失模块或数据的异常掩盖 HTTP 435 / 403。
- **Google 搜索 / Google Jobs**：HTTP 200 的 `/sorry/` 验证页不再被当作空搜索结果；修复后真实复测均明确返回 `TARGET_BLOCKED`。搜索分页出错也不再静默返回部分结果。
- **DHL 测试配置**：可通过 `DHL_TRACKING_NUMBER` 提供当前有效且获准使用的样例；本轮按用户要求跳过后续验证。

## 验证证据与边界

- **整套通过**：Google Play 3/3、Google Flights 2/2、Maersk 2/2、Crunchbase 2/2。它们证明当天这些现有用例成功，不代表站点所有功能或未来可用性。
- **Google Play 备用路径**：另外注入一次 CDP 隧道失败，随后调用真实 AdsCrawl HTML API（US）取得 WhatsApp 应用 ID、名称、开发者和评分数量。故障触发为模拟，后续 API 请求与返回数据为真实；JSON 单独记录，未混入整套通过数。
- **离线回归**：本次新增 18 项回归测试全部通过。[最终代码的 GitHub Actions](https://github.com/AdsCrawl/adscrawl-scrapers/actions/runs/42977694198) 通过 Python 3.10、3.12、3.13 的离线测试、81 站目录检查及构建。离线通过不代表在线目标可访问。
- **远程会话**：记录到 186 个本任务会话；收尾查询时任务所属活跃会话为 0，账号会话列表也为空。未关闭其他任务会话。
- **证据保护**：不公开 API Key、CDP URL、会话 ID、Cookie 或原始调试日志。历史 `results/` 样例未作为本次结果，也未覆盖。公开 JSON 仅包含安全的测试元数据与少量已核验输出字段。

初始 16 站及针对性复测每站限时 360 秒；其他 50 站每站限时 180 秒，并在首个失败后停止该站剩余用例。超时后最多留 45 秒退出与清理。最多两个站点进程并行，每个进程 `ADSCRAWL_CONCURRENCY=1`；pytest 使用 `--reruns=0`。站点实现内部的重试仍会执行。

默认 `ADSCRAWL_DEFAULT_COUNTRY=US`；站点显式设置的国家优先，例如 Goibibo 使用 IN。JSON 的 `countries` 来自真实创建的会话设置。每个用例采用最新一次已结束结果；只有最新整套运行正常退出且通过才算“整套通过”。离线 URL/解析测试不计入在线通过数。限时内没有结束的用例不算通过，`1 / 1` 的“部分通过”也不表示该站全部用例已完成。

## 尚未解决的限制

403、429、435、验证页、代理隧道失败和超时仍阻止部分真实工作流完成；本次代码修复没有使这些目标自动恢复可访问。Immowelt 的旧房源样例返回 410，寻找替代房源的搜索请求也返回 403；DHL 按要求暂停验证。对这些站点应先解决可访问路径或取得有效测试样例，再重跑完整验收。

复测示例（会产生真实 AdsCrawl 用量）：

```bash
export ADSCRAWL_API_KEY="your_api_key"
export ADSCRAWL_DEFAULT_COUNTRY=US
export ADSCRAWL_CONCURRENCY=1
SELECTED_SCRAPER=google-play-scraper python scripts/live_test.py
```

对外引用请同时保留日期、具体用例、国家及状态，不要把解析器修复、离线 CI 通过或某一次单项成功表述为全站稳定可用。
